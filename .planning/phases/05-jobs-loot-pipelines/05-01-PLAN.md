<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ATS/aggregator listings → adapter → tick | Untrusted external job data enters the ingestion pipeline (title/snippet, then full detail text) |
| Fetched detail text → LLM audit prompt | Untrusted content crosses into the LLM prompt and its verdict crosses back |
| Orchestrator → PocketBase/Turso writes | Service-account writes create opportunities rows and tombstones; replay could duplicate or corrupt state |
| Scheduler registry → orchestrator drain | Injected tickHandler is the only call path; cadence and overlap guards bound execution |
| Env + logs | Channel IDs and tokens flow through env parsing and structured logs |

## STRIDE Threat Register

Threat IDs are unique within Phase 5; T-05-01..T-05-07 are allocated to this plan; T-05-SC is reserved for the phase-wide supply-chain row.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | Job text → LLM verdict (orchestrator.ts, rule-packs/jobs.ts) | high | mitigate | Rule-pack system prompt marks candidate text as untrusted data and never instructions; parseJobsVerdict zod-validates the verdict shape; deterministic gates hold final authority over routing and reject codes |
| T-05-02 | Tampering | Outbound fetch targets (greenhouse.ts, tick fetch path) | high | mitigate | Every outbound fetch stays behind the existing validateUrl SSRF guard + the sanitize fetch facade; detail fetch hosts are fixed ATS endpoints; failures degrade to []/null, never throw |
| T-05-03 | Information Disclosure | Env + logs (logger; .env.example drift fixed in 05-08) | medium | mitigate | Channel IDs and secrets never logged; .env.example placeholders only, key additions land in 05-08 and stay bijective with EnvSchema (guard in plan 05-06) |
