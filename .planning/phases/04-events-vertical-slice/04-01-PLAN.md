<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Portal listings → adapter | Untrusted external event data from national portals enters the ingestion pipeline |
| Link-Hopper redirect following | HTTP Location headers from external servers are followed; SSRF risk on hop targets |
| Discord bot token | DISCORD_TOKEN is the sole auth for the Discord Gateway; leakage impersonates the alert system |
| Discord gateway connection | Outbound WebSocket to Discord Gateway; bot must be in target guild with channel permissions |
| PocketBase writes | Service-account PB writes transition status audited→routed; replay could duplicate alerts |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Spoofing | Discord bot token (DISCORD_TOKEN) | high | mitigate | Env-only secret via zod EnvSchema.parse fail-fast; DISCORD_TOKEN in REDACT_PATHS; .env gitignored; .env.example placeholders only |
| T-04-02 | Tampering | Link-Hopper redirect following (link-hop.ts) | high | mitigate | validateUrl SSRF guard on every hop target (rejects private/loopback, non-80/443 ports); max 2 hops; failed resolution → tombstone link_hop_failed |
| T-04-03 | Repudiation | Discord router status transition (router-service.ts) | medium | mitigate | Router service marks status='routed' after successful embed post; failed posts retry via recordFailure (5 → tombstone), preventing duplicate posts |
