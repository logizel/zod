           - Parse the command: `!rule BLOCK <text>` or `!rule BOOST <text>` or `!rule WEIGHT <value> <text>` or `!rule CUSTOM <text>`.
           - `const parsed = parseRuleCommand(msg.content);` — returns `{ kind, rule, weight }`.

           - `pb.collection('taste_rules').create({ kind: parsed.kind, rule: parsed.rule, weight: parsed.weight ?? 1.0, source: 'dm' })`.
           - `msg.reply('✅ Taste rule created: ${parsed.kind} — ${parsed.rule}')` — confirmation in the DM.
       - Export `parseRuleCommand(content: string): { kind: string; rule: string; weight?: number }` for testability.

  <files>packages/orchestrator/src/taste-apply.ts, packages/orchestrator/src/taste-apply.test.ts, packages/orchestrator/src/rule-packs/events.ts, packages/orchestrator/src/orchestrator.ts, packages/orchestrator/src/orchestrator.test.ts</files>
  <action>
    Create the taste rule application module that implements the hybrid model: BLOCK rules as pre-scoring filters and BOOST/WEIGHT/CUSTOM rules as system-prompt injections, with D-12/D-13 precedence reconciled.

    **per D-12** — Taste rule application is hybrid: BLOCK rules = pre-scoring filter (checked before LLM runs; auto-rejects + tombstones, never reaches the auditor — saves free-tier LLM quota). BOOST/WEIGHT/CUSTOM rules = system-prompt injection (appended to auditor's system prompt as advisory signals; LLM retains final judgment).

    **per D-13** — Taste rule precedence: Taste BLOCK overrides soft/personal gates but NOT hard compliance gates. Hard gates (2+yr roles, unpaid non-fellowships, pay-to-training, US/EU-only swag) are mission-non-negotiable per PROJECT.md out-of-scope and cannot be overridden by taste rules.

    **Precedence order (reconciled D-12 + D-13):**
    1. Hard compliance gates FIRST (mission-non-negotiable — cannot be overridden by any taste rule).
    2. Taste BLOCK pre-scoring filter SECOND (overrides soft/personal gates only — e.g. organizer_score thresholds, agenda_score thresholds, personal preferences).
    3. Soft gates THIRD.
    BOOST/WEIGHT/CUSTOM rules are always advisory system-prompt injections; LLM retains final judgment.

    **Implementation steps:**

    1. **`packages/orchestrator/src/taste-apply.ts`** — Create the taste rule application module:
       - Export `loadTasteRules(pb: PbLike): Promise<TasteRule[]>` — fetch all taste_rules rows from PB: `pb.collection('taste_rules').getList(1, 200, { sort: '-created' })`.
       - Export `checkBlockRules(candidates: PollCandidate[], rules: TasteRule[]): { blocked: PollCandidate[]; passed: PollCandidate[] }` — pre-scoring filter:
         - For each candidate, check against each BLOCK rule.
         - A BLOCK rule matches when the candidate title or snippet contains the rule text (case-insensitive substring match: `cand.title.toLowerCase().includes(ruleText.toLowerCase()) || cand.snippet.toLowerCase().includes(ruleText.toLowerCase())`).
         - Matching candidates → `blocked` array (will be tombstoned, never sent to LLM).
         - Non-matching candidates → `passed` array (proceed to normal pipeline).
       - Export `buildTastePromptInjection(rules: TasteRule[]): string` — system-prompt injection:
         - Filter rules to BOOST/WEIGHT/CUSTOM kinds only.
         - Format as advisory text: `'\n\nOperator taste rules (advisory, not authoritative):\n' + rules.map(r => '- ${r.kind}: ${r.rule} (weight: ${r.weight})').join('\n')`.
         - Return empty string if no rules to inject.
       - Export `applyTastePreScoring(candidates: PollCandidate[], rules: TasteRule[], pb: PbLike, url: string): Promise<PollCandidate[]>` — full pre-scoring flow:
         - Check BLOCK rules against each candidate.
         - For blocked candidates: write tombstone (`terminal_status: 'taste_blocked'`, `source: 'taste_rule'`) and remove from the candidate list.
         - Return only the passed candidates.

    2. **`packages/orchestrator/src/rule-packs/events.ts`** — Extend the events rule pack for taste injection:
       - Extend `EventsCtx` with an optional `tasteInjection?: string` field.
       - In `buildEventsMessages`, if `tasteInjection` is non-empty, append it to the system prompt content: `system.content += tasteInjection`.
       - The injection is advisory — the LLM retains final judgment (per D-12).

    3. **`packages/orchestrator/src/orchestrator.ts`** — Wire taste rules into the audit pipeline with reconciled precedence:
       - In `processEventsRow` (and `drainLocalRow`, `processJobsRow`, `drainLootRow`):
         a. **Hard compliance gates FIRST** (before taste rules) — 2+yr roles, unpaid non-fellowships, pay-to-training, US/EU-only swag are mission-non-negotiable; cannot be overridden by taste rules (D-13).
         b. **Before LLM call:** Load taste rules via `loadTasteRules(pb)`. Run `checkBlockRules` on the candidate. If blocked → tombstone `taste_blocked`, advance to STEP_3, return (never call LLM — saves quota). This is the taste BLOCK pre-scoring filter (D-12).
         c. **At message build time:** Load BOOST/WEIGHT/CUSTOM rules via `buildTastePromptInjection(rules)`. Pass the injection string into `buildEventsMessages` (and `buildJobsMessages`, `buildLootMessages`, `buildLocalMessages`) via the ctx `tasteInjection` parameter.
         d. **Soft gates LAST** — taste BLOCK overrides soft/personal gates only (organizer_score thresholds, agenda_score thresholds); hard gates already applied in step (a) and cannot be overridden (D-13).

    **Do NOT:**
    - Do NOT let BLOCK rules override hard compliance gates (2+yr roles, unpaid non-fellowships, pay-to-training, US/EU-only swag) — per D-13, these are mission-non-negotiable.
    - Do NOT send BLOCKed candidates to the LLM — the pre-scoring filter tombstones them before the auditor runs, saving free-tier quota.
    - Do NOT concatenate taste rules into the user message — they go into the system prompt as advisory signals only (per T-6-11).
    - Do NOT make taste rules authoritative — the LLM retains final judgment (per D-12).
