  <name>Task 1: Bookmark reaction handler — custom emoji → bookmark=true + arm deadline reminders</name>
  <files>packages/discord-router/src/bookmark.ts, packages/discord-router/src/gateway.ts</files>
  <action>
    Create the bookmark reaction handler that listens for messageReactionAdd with the custom bookmark emoji on audit cards, sets bookmark=true on the opportunity row, and arms deadline reminders.

    **per D-05** — Bookmark emoji is a custom server emoji (not unicode 📌) to avoid rendering issues across Discord clients. Bot listens for MessageReactionAdd with the custom emoji on audit cards, sets bookmark=true on the opportunity row, arms deadline reminders.

    **per D-06** — Reminder anchor is the event date: 48h/24h deadline reminders count down to deadlines.event_start / deadlines.apply_by (the actual deadline, not post time). Reminders stored in opportunities.reminders[] with { at, channel, sent } shape.

    **Implementation steps:**

    1. **`packages/discord-router/src/bookmark.ts`** — Create the bookmark handler:
       - Export `startBookmarkHandler(deps: { env: Env; log: Logger; pb?: any; client?: any }): BookmarkHandler`.
       - Resolve the discord.js Client via `getClient()` from gateway.ts (or inject via deps for tests).
       - Register `client.on('messageReactionAdd', async (reaction, user) => {...})`:
         a. **Guard:** `if (user.bot) return;` — only non-bot users trigger bookmarks (per T-6-04).
         b. **Guard:** `if (reaction.emoji.id !== env.BOOKMARK_EMOJI_ID) return;` — only the custom emoji triggers.
         c. **Handle partial messages (per Pitfall 2):** `if (reaction.message.partial) { try { await reaction.message.fetch(); } catch { return; } }`.
         d. **Find the opportunity:** Look up the opportunities row by the message ID. The router service's `processOpportunity` sends the embed to Discord — the response from `channel.send()` contains the sent message ID. Store this message ID on the opportunity row (add a `discord_message_id` field or use the existing schema). Query: `pb.collection('opportunities').getList(1, 1, { filter: "discord_message_id = '${reaction.message.id}'" })`.
         e. **Set bookmark + arm reminders:**
            - Compute reminders from `opportunity.deadlines` (per D-06):
              - anchor = deadlines.event_start ?? deadlines.apply_by
              - If anchor exists: r48 = new Date(anchor - 48h), r24 = new Date(anchor - 24h)
              - Only include reminders where the reminder time is in the future
              - Each reminder: `{ at: reminderTime.toISOString(), channel: opportunity.bucket_channel, sent: false }`
            - Update: `pb.collection('opportunities').update(opp.id, { bookmark: true, reminders: computedReminders })`
         f. **Confirmation reply:** `await reaction.message.reply('🔖 Bookmarked — you will get 48h and 24h reminders before the deadline.')`.
       - Return a stop handle.

    2. **`packages/discord-router/src/gateway.ts`** — Ensure the bookmark handler starts at boot:
       - The gateway already includes `GatewayIntentBits.GuildMessageReactions` (added in Plan 01 Task 1).
       - After `client.login()`, call `startBookmarkHandler({ env, log })` alongside the existing service startup.
       - Alternatively, export `startBookmarkHandler` and call it from the entrypoint alongside `startRouterService` — follow the existing pattern.

    3. **`packages/discord-router/src/router-service.ts`** — Store the Discord message ID on the opportunity row:
       - In `processOpportunity`, after `channel.send({ embeds: [embed] })`, capture the returned message: `const sentMessage = await channel.send({ embeds: [embed] });`
       - Update the opportunity row with the Discord message ID: `pb.collection('opportunities').update(opportunity.id, { status: 'routed', discord_message_id: sentMessage.id })`.
       - This enables the bookmark handler to find the opportunity by reaction message ID.

    **Do NOT:**
    - Do NOT use unicode 📌 — D-05 explicitly chooses custom server emoji for cross-client rendering consistency.
    - Do NOT allow bot reactions to trigger bookmarks — `if (user.bot) return;` is mandatory.
    - Do NOT arm reminders in the past — only future reminder times are included.
    - Do NOT skip partial message handling — reactions on uncached messages need `reaction.message.fetch()`.

<task type="auto">
  <name>Task 2: Reminder ticker — scan reminders[] and fire 48h/24h deadline posts</name>
  <files>packages/discord-router/src/reminder.ts, packages/scheduler/src/jobs.ts</files>
  <action>
    Create the reminder ticker that scans bookmarked opportunities and fires deadline reminders at the scheduled times.

    **per D-06** — 48h/24h deadline reminders count down to deadlines.event_start / deadlines.apply_by (the actual deadline, not post time). Reminders stored in opportunities.reminders[] with { at, channel, sent } shape.

    **Implementation steps:**

    1. **`packages/discord-router/src/reminder.ts`** — Create the reminder ticker:
       - Export `reminderTick(opts: { env: Env; log: Logger; pb?: any; client?: any }): Promise<void>`.
       - Scan `opportunities` collection: `filter: "bookmark = true"`, page size 50, sort by `updated`.
       - For each bookmarked opportunity:
         a. Find reminders where `sent === false` and `at <= now` (compare ISO timestamps).
         b. For each due reminder:
            - Resolve the channel via the same `resolveChannel` pattern from router-service.ts (env-ID-first via CHANNEL_ID_ENV_KEYS, then exact-name fallback).
            - Send the reminder message: `channel.send({ content: '⏰ Reminder: **${opp.title}** — ${formatReminder(reminder, opp.deadlines)}' })`.
            - **Mark as sent immediately (per Pitfall 6):** Update `reminders[].sent = true` right after posting. Use the array map pattern: `opp.reminders.map(r => r.at === reminder.at ? { ...r, sent: true } : r)`.
            - `pb.collection('opportunities').update(opp.id, { reminders: updatedReminders })`.
         c. Handle errors per-opportunity (never abort the batch).
       - The `formatReminder` function produces human-readable text like "Event starts in 48h (2026-10-18)" or "Apply by in 24h (2026-10-17)".

    2. **`packages/scheduler/src/jobs.ts`** — Register the reminder-tick job:
       - Add a new entry to STUB_JOBS (or a new REMINDER_JOBS array registered through the same registry):
         - `name: 'reminder-tick'`
         - `expression: '*/15 * * * *'` (every 15m + 5m jitter — reminders are time-sensitive but not second-critical)
         - `maxRandomDelayMs: 5 * 60_000`
         - `description: 'bookmark deadline reminder scan (UI-02)'`
       - The reminder tick is a service tick (uses getClient() + PB), so it should use the same pattern as relay-poll: register via a `registerReminderJob` function in registry.ts that uses `runGatewayTick` with a tickHandler that calls `reminderTick()`.

    **Do NOT:**
    - Do NOT fire reminders where sent=true — the filter and the immediate update prevent double-firing (per Pitfall 6).
    - Do NOT create a new scheduler job outside the registry — all cron goes through registry.ts.
    - Do NOT send reminders to DM channels — reminders go to the opportunity's bucket_channel.
